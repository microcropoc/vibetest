# vt-3 — Общий контракт движка шага (без UI)

## Контекст

Плеер будет делегировать логику шага доменным «движкам». Нужен единый контракт для всех типов: состояние, завершение, ошибка, повтор — без Angular-компонентов и без наследования классов.

## Цель

В домене появляется типизированный контракт step engine (pure functions / readonly state): инициализация из parsed step + опционального сохранённого прогресса, команды, переходы, признак `completed`, неудачная проверка (quiz/практика), сброс «Повторить». **Без registry** и без знания конкретных типов шагов — только общие типы, reduce/helpers и discriminated union расширений.

## Требования

- Контракт описывает: вход (parsed step + опциональный сохранённый прогресс), текущее состояние, команды (`advance`, `retry`, `submitAnswer` и т.п. — минимальный общий набор + расширения через discriminated union по `type`).
- Инварианты: theory/svg завершение по явному advance; quiz/practice — completed только после успешной проверки; retry сбрасывает черновик и флаг неудачной проверки, не ломая уже `completed` при тренировке (как в спецификации).
- Тесты на переходы состояний и инварианты **без TestBed**.
- Не использовать абстрактный базовый класс; предпочтение functions + types.

## Технические заметки

- Папки: `player/` или `courses/` + общий модуль `step-engine/` (уточнить при старте, без лишних слоёв).
- Зависимость: **vt-2** (типы шага/курса из Zod).
- Типы шагов из схемы; `unknown` только на границе до parse.
