# Отчёт vt-79 — Ручной поэтапный режим с импортом на странице «Генерация промта»

## Что сделано

- `StagedStepAcceptor` (`course-generation/staged-step-acceptor.service.ts`): `acceptFirstModule` (курс ровно с одним модулем, сохранение с новыми UUID) и `acceptModule` (модуль в конец курса, удалённый курс — fatal), плюс чистая функция `extractModelJson(raw, contextHint)`. Код перенесён из `StagedCourseGenerator`, который теперь вызывает эти функции; его поведение и spec не изменились.
- `ManualStagedProgress` (`prompt-generation/manual-staged-progress.ts`, Zod): описание, ответ с планом, id курса, номер следующего модуля. Хранится в `settings` под ключом `manualStagedProgress`; `SettingsRepository.get/set/clearManualStagedProgress`, битая строка читается как «нет прогресса».
- Dumb-компонент `ManualStagePanel` (`prompt-generation/ui/manual-stage-panel`): название этапа, «Копировать промт» / «Копировать промт с исправлениями», поле ответа, «Проверить и сохранить», проблемы и ошибка, статус копирования.
- Страница «Генерация промта», режим «Поэтапно»: вместо списка промтов модулей — мастер «Курс и модули»:
  - список этапов со статусом;
  - панель текущего этапа: сначала курс с модулем 1, затем модули по порядку;
  - ссылка «Открыть курс», «Курс готов» после последнего модуля.
- Неверный ответ: проблемы показываются в панели, промт копируется с retry-заметкой (`retryIssues`), попытки не ограничены.
- После сохранения курса описание и ответ с планом блокируются.
- Прогресс пишется в IndexedDB через `effect()` после восстановления; при открытии страницы восстанавливается, при наличии плана или курса включается «Поэтапно». «Начать заново» очищает форму и прогресс, курс остаётся.
- SPECIFICATION.md: раздел «Генерация промта» и ключ `manualStagedProgress` в таблице `settings`.

## Отклонения от TASK.md

- У панели есть необязательный вход `hint`, его страница пока не использует.
- Страница переключается в «Поэтапно» при восстановлении, только если есть ответ с планом или сохранённый курс: одно описание — не повод уходить из режима «Одним промтом».
- Описание блокируется после сохранения курса в обоих режимах, так как поле общее; под ним подсказка про «Начать заново».

## Открытые вопросы к ревью

- Прогресс пишется в IndexedDB на каждое изменение описания и ответа с планом, без debounce. Для текстовых полей такого размера это дёшево, но при желании можно писать только на blur или при сохранении этапа.
- Вставленный ответ текущего этапа не сохраняется в прогресс: после перезагрузки его нужно вставить снова.

## Изменения по ревью

Ревью (2026-10-07):

- Форма доступна до чтения прогресса из IndexedDB → `prompt-generation-page.ts` (`loadSchemas` / `restoreProgress`), шаблон прячется только за `loading()` схем → не показывать поля, пока `progressRestored` не станет true. Иначе при более быстром ответе схем пользователь видит пустую форму и ввод затирается восстановленными описанием и планом.
- Успешное сохранение курса или модуля не ждёт запись прогресса, ошибка записи проглатывается → `onAcceptStage` / `onStartOver` и `effect()` с `write.catch(() => undefined)` → `await` `setManualStagedProgress` / `clearManualStagedProgress` до перехода к следующему этапу и до сообщения, что прогресс сохранён; при ошибке показать её. Сейчас курс уже в `courses`, а `manualStagedProgress` может остаться старым (закрытие страницы до коммита или сбой IndexedDB): следующий заход повторит этап. Для этапа 0 `acceptAnswer` при `step.index === 0` снова вызывает `acceptFirstModule` и создаёт второй курс, даже если `courseId` уже есть.
- Режим «Одним промтом» запоминает описание между визитами → тот же `effect()` пишет `manualStagedProgress` при любом непустом описании, без плана и курса → по TASK режим не меняется, в «Отклонениях» этого нет. Не писать прогресс, пока нет плана или курса, либо явно описать восстановление общего поля в SPEC и в отклонениях.

### Исправлено (раунд 1)

1. Форма и режимы показываются только когда `pageReady` (схемы загружены и `progressRestored`); до этого — «Загрузка…». Схемы и прогресс грузятся параллельно в `initializePage()`.
2. Автосохранение через `effect()` убрано. `persistProgressOrThrow()` вызывается явно после успешного этапа (`await` до перехода дальше), при изменении плана/описания (если прогресс нужно хранить) и при «Начать заново» (`await clear`). Ошибки записи — в `progressError` или в `stageError` после сохранённого этапа. `acceptAnswer` для этапа 0 не вызывает `acceptFirstModule`, если `courseId` уже есть.
3. `shouldPersistManualStagedProgress`: в IndexedDB пишется только при непустом `outlineResponse` или сохранённом `courseId`; одно описание в режиме «Одним промтом» не сохраняется. Тест добавлен. `ng test --watch=false` — зелёный.

Ревью (2026-10-07, раунд 2):

- После успешного импорта мастер уже сдвинут, а сбой записи прогресса кладётся в `stageError` → `onAcceptStage` в `prompt-generation-page.ts` (`courseId` / `nextModuleIndex` до `await persistProgressOrThrow`, `catch` пишет `stageError`) → панель с `[error]` есть только у `currentStep()`. На последнем модуле `currentStep()` становится `null`, страница показывает «Курс готов», текст ошибки не отображается (`progressError` при этом не ставится). Ожидание: не показывать завершение этапа, пока запись прогресса не прошла; ошибку выводить туда, где её видно и при «Курс готов» (например `progressError`); повторная попытка должна дописывать прогресс и не вызывать `acceptFirstModule` второй раз. Иначе обновление страницы после такого сбоя повторяет этап и создаёт второй курс или лишний модуль.

### Исправлено (раунд 2)

1. После успешного импорта `onAcceptStage` вызывает `commitProgress(next)`: сначала `setManualStagedProgress`, и только после успешной записи обновляются `courseId` / `nextModuleIndex` (мастер переходит дальше, этап становится «готово», на последнем модуле — «Курс готов»).
2. При сбое записи прогресс кладётся в `pendingProgress`, ошибка — в `progressError` (блок под этапами, виден всегда), рядом кнопка «Повторить запись прогресса». Панель этапа скрыта (вместо неё — пометка, что этап сохранён в курсе и ждёт записи прогресса), «Курс готов» не показывается, описание и план заблокированы.
3. `onRetryProgress` пишет тот же `pendingProgress` без повторного импорта; `onAcceptStage` игнорируется, пока есть `pendingProgress`. «Начать заново» сбрасывает ожидание.
4. Тесты: сбой записи после курса (панели нет, курс один, повтор → «Модуль 2 из 3», прогресс записан, курс всё ещё один) и после последнего модуля («Курс готов» нет до успешного повтора, модулей 3). SPEC дополнена. `ng test --watch=false` — 644 теста, зелёный.
