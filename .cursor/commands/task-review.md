# vibetest — код-ревью vt-*

Ввод пользователя: `$ARGUMENTS` (например `vt-83` или пусто — тогда из текущей ветки `feature/vt-{n}-{slug}`).

Критерии кода — в `.cursor/rules/angular-cli.mdc`; здесь — процесс и выход.

## Скоуп задачи

1. Определить `vt-{n}` из `$ARGUMENTS` или текущей ветки `feature/vt-{n}-{slug}`.
2. Папка задачи: `docs/tasks/in-progress/vt-{n}-{slug}/` (`TASK.md`, `REPORT.md`).
3. Если только в `done/` — ревьюить только если пользователь явно указал эту задачу.

## Что прочитать

- `TASK.md`, `REPORT.md` задачи
- Релевантные разделы `docs/SPECIFICATION.md`
- Дифф относительно `main` (см. ниже)

## Дифф (обязательно оба слоя)

**Закоммиченное на ветке** (вся история задачи на feature-ветке, включая последний коммит после `/task-implement`):

- `git log main..HEAD` — все коммиты ветки относительно `main`
- `git show HEAD` — последний коммит на ветке (типично свежая реализация или правки после ревью)
- `git diff main...HEAD` — полный дифф ветки vs `main`

**Незакоммиченное** (если implement/review-fix ещё не закоммичены):

- `git status`
- `git diff`
- `git diff --cached`

Ревьюить и то, и другое.

## Критерии (чеклист)

- Соответствие `TASK.md` и SPEC; отклонения осознанны и отражены в REPORT
- Архитектура: standalone, domain folders, lazy pages, smart/dumb, storage vs domain, execution/Workers
- Стиль: strict TS, no `any`, `unknown` + parse at boundaries, signals/zoneless
- Тесты: поведение, colocated specs; при изменении логики — ожидание зелёного `ng test` где уместно
- Git/hygiene: правки `vibetest-app/` только на feature-ветке задачи; без лишнего scope

## Выход: только секция «Изменения по ревью»

Обновить **только** `## Изменения по ревью` в `REPORT.md` задачи:

- Убрать плейсхолдер; записать **список замечаний** (или «Замечаний нет.»)
- Формат пункта: **что** не так → **где** (файл/область) → **ожидание** / почему
- При повторном ревью: **дописать** новые пункты или заменить список по согласованию с пользователем; не затирать «что исправлено», если разработчик уже заполнил секцию — добавлять блок «Ревью (дата/раунд): …» при необходимости

**Запрещено в режиме ревью (без явной просьбы пользователя):**

- Править код, тесты, `TASK.md`, SPEC, другие секции REPORT
- Коммит, merge, перенос папок задач

## Ответ в чате

Кратко: **ok** / **есть замечания** + что записано в REPORT. Не дублировать длинный список, если он уже в файле.
