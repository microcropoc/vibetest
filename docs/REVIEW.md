## Замечания

### Высокий приоритет (технические риски)

1. **vt-2 — конвертер JSON Schema → Zod может не покрыть схему.** Используются: `if`/`then` для дискриминации `content` по `type` (`allOf` из 6 веток), `uniqueItems` (quiz). Популярные конвертеры (например, json-schema-to-zod) `if/then` не поддерживают. Spike в карточке предусмотрен — это правильный первый шаг. Зафиксировать fallback заранее: ручной `z.discriminatedUnion('type', …)` поверх сгенерированных частей + типы через json-schema-to-typescript + smoke-тест эквивалентности Zod ↔ JSON Schema через Ajv на общих фикстурах.
2. **vt-12: helper удаления прогресса должен быть транзакционно-композабельным.** vt-15 требует replace **одной** транзакцией (`deleteAllByCourseId` + `CourseRepository.put`). Если helper vt-12 будет сам открывать транзакцию только над `stepProgress`, в vt-15 его придётся переделывать. Дописать в требования vt-12: helper вызывается внутри внешней `db.transaction('rw', [courses, stepProgress], …)` (или принимает таблицу/контекст), сам транзакцию не открывает.

### Средний приоритет (уточнить в карточках)

3. **Strict TS в scaffold отсутствует.** Ни `tsconfig.json`, ни `tsconfig.app.json` не содержат `strict: true` (правило проекта strict требует). Закрывается требованием vt-2 — порядок корректный, но это подтверждает, что vt-2 должен идти первым кодовым изменением и никакой код до него писать нельзя.
4. **vt-2, semantic rule «reset без SQL INSERT/seed» — эвристика без точной дефиниции.** Поиск по подстроке даст false positives в JS-коде (`insertAdjacentHTML`, переменная `insert`). Определить точно (например, регистронезависимо, с границей слова `\bINSERT\b`/`\bINTO\b`) и зафиксировать в REPORT vt-2 — иначе проверка будет вести себя непредсказуемо для авторов курсов.
5. **vt-9: sql.js требует `.wasm` как asset + `locateFile`.** Нужна правка `angular.json` (assets) — правило допускает при необходимости, но сейчас в карточке пункта нет. Добавить: подключение sql.js, раздача wasm, загрузка внутри Worker. (Кэширование WASM в vt-27 уже учтено.)
6. **vt-16: дефолтный `app.spec.ts` сломается.** Тест scaffold'а проверяет `h1` с «Hello, vibetest-app» — при замене шаблона на shell упадёт. Добавить в план vt-16 пункт «обновить/удалить дефолтный spec».
7. **Дублирование confirm-диалога.** vt-17 (удаление курса) и vt-24 (replace confirm) оба требуют диалог подтверждения; правило запрещает дублирование. Предложение: в vt-17 создать dumb `ConfirmDialogComponent` в `shared/ui/`, в vt-24 дописать «переиспользовать confirm из shared/ui».

### Низкий приоритет / опционально

8. **vt-23 ↔ vt-20:** текст vt-23 ссылается на кнопку «Повторить» из vt-20, но в `PLAN.md` deps vt-23 — только vt-8–vt-10, vt-19. При последовательном порядке некритично (vt-20 раньше); для параллельного сценария добавить vt-20 в deps vt-23.
9. **vt-14 deps:** типы draft/state — из vt-3 (`player/step-engine/`), в deps указаны vt-11/12/13 (vt-3 приходит транзитивно через vt-13). Работает; для ясности можно указать vt-3 явно.
10. **vt-7:** зафиксировать в REPORT способ бандлинга worker'ов в Angular/esbuild (`new Worker(new URL('./x.worker.ts', import.meta.url), { type: 'module' })`); моки для Vitest уже предусмотрены карточкой.
11. **Открытый вопрос vt-1 без ответа:** локально Node v26 (Current), не LTS. Решить в рамках vt-2: `.nvmrc` или `engines` в `package.json`.
12. **Prettier** есть в devDependencies, но нет конфига и format-скрипта — добавить `.prettierrc` + npm-скрипт или убрать зависимость.
13. **Дизайн-токены:** цвета индикаторов плеера (текущий/ошибка/пройден/не тронут) и общие стили понадобятся в vt-17…vt-26. Опционально: минимальные SCSS-токены в vt-16 или vt-20, чтобы страницы не разъехались визуально.
