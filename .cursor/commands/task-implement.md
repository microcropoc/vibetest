# Реализация задачи vt-*

Ввод пользователя: `$ARGUMENTS`

Инварианты и формат ревью — `.cursor/rules/angular-cli.mdc`. Спецификация: `docs/SPECIFICATION.md`.

## Режим (первый шаг)

1. Определи `vt-{n}-{slug}` из `$ARGUMENTS` или ветки `feature/vt-{n}-{slug}`.
2. Если есть `docs/tasks/in-progress/vt-{n}-{slug}/` — **сначала только `REPORT.md`** (не открывай `TASK.md` / SPEC до выбора):
   - Последний `### Ревью N (…)` содержит **`Замечаний нет.`** → **готово к merge**: ничего не менять, предложи `/task-merge`.
   - Последний `### Ревью N` **без** следующего `### Исправлено N` → **режим Б** (правки по ревью).
   - Иначе → **режим А** (реализация / продолжение по TASK).
3. Если задачи нет в `in-progress/` (только `backlog/`) → **режим А**.

## Режим Б — правки по ревью

1. Только пункты последнего `### Ревью N`; `TASK.md` / SPEC — только если замечание явно ссылается.
2. Исправь код и тесты; допиши **`### Исправлено N`** под этим раундом (другие секции REPORT не трогать).
3. `ng test --watch=false` в `vibetest-app/` при изменении кода или тестов; обнови `## Тесты` при необходимости.
4. Коммит: `vt-{n}: …` (фиксы ревью), если есть изменения.

## Режим А — реализация

### Старт из backlog

1. `git switch main && git pull --ff-only`
2. `git switch -c feature/vt-{n}-{slug}`
3. `git mv docs/tasks/backlog/vt-{n}-{slug}.md` → `docs/tasks/in-progress/vt-{n}-{slug}/TASK.md`
4. `REPORT.md` из `docs/tasks/_template/REPORT.md` (frontmatter `branch: feature/vt-{n}-{slug}`)

### Работа

1. `TASK.md`, релевантные разделы SPEC, `REPORT.md`.
2. Реализация по TASK; обновляй REPORT (кроме `## Изменения по ревью`).
3. `ng test --watch=false` в `vibetest-app/` при изменении логики или тестов; `## Тесты` в REPORT.
4. Коммит на feature-ветке: `vt-{n}: …`, если есть изменения.

## Запрещено без явного запроса

`/task-merge`, push, перенос в `done/`.

## Ответ в чате

Режим (**А**, **Б** или **готово к merge**), ветка, сделано, тесты, хеш последнего коммита; для А — что осталось по TASK; для Б — закрытые пункты ревью.
